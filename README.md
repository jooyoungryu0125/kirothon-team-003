# 아무거나 말고 🦍

> "아무거나"라고 말하면서 사실 다 생각 있잖아요.  
> 정하기 싫을 때, 아무고릴라한테 맡겨봐요.

소규모 그룹의 사소한 결정을 돕는 카드 투표 웹앱이에요.  
방장이 주제를 정하고, 참여자가 후보를 올리고, 카드 버튼으로 투표하면 — 거부권과 동점 규칙으로 딱 하나의 결론이 나와요.

## 🤔 문제 정의

> "오늘 뭐 먹지?" — "아무거나." — "아무거나 말고."

2~6명이 모였을 때 사소한 결정을 내리지 못해 시간을 낭비하는 상황은 흔해요.  
투표 앱은 많지만, **후보를 함께 모으고 → 익명으로 투표하고 → 거부권까지 행사해서 → 단 하나의 결론**을 내는 흐름을 한 번에 처리하는 가벼운 도구는 없었어요.

## ✨ 핵심 기능

### 방 만들기와 참여
- 방장이 주제 종류(메뉴 🍽️ · 영화 🎬 · 장소 📍 · 직접 입력 ✏️)를 선택해 방을 만들어요.
- 참여자는 4자리 방 코드와 닉네임만으로 로그인 없이 입장해요.
- 한 방에 최대 **6명**까지 참여할 수 있어요.

### 후보 제출
- 참여자마다 후보를 최대 **3개**, 각 후보에 어필멘트(선택)를 붙여 한 번에 제출해요.
- 제출은 1인 1회만 가능하고, 제출 전까지 다른 사람의 후보는 보이지 않아요.

### 중복 후보 자동 통합
- 투표 시작 시, 이름이 같은 후보(공백·대소문자 무시)를 하나로 합쳐요.
  - 예: `마라탕` / `마 라 탕` → 하나의 후보로 통합
- 통합된 후보의 어필멘트는 모두 순서대로 보존돼요.

### 카드 투표
- 후보 카드를 한 장씩 보며 하단의 **싫어 👎 / 좋아 💗 버튼**으로 선택해요.
- 카드를 탭하면 앞면(이름) ↔ 뒷면(어필멘트)이 뒤집혀요.
- 카드 번호와 전체 개수가 진행 표시줄과 함께 표시돼요.

### 거부권
- 싫어요를 선택한 후보 중 딱 **1개**에 거부권을 행사할 수 있어요.
- 거부권을 받은 후보는 결과에서 제외돼요.

### 결과 결정 규칙
1. 거부권을 받은 후보 제외
2. 남은 후보를 좋아요 수 내림차순으로 정렬
3. 같으면 싫어요 수 오름차순으로 정렬
4. 여전히 1등이 동점이면 → 동점 후보와 어필멘트를 공개한 뒤 **랜덤**으로 최종 1등 결정
5. 모든 후보가 거부권을 받은 경우 → 가장 적게 받은 후보들에서 2~4번 적용

### 결과 화면
- 두구두구 연출(5초) 후 👑 최종 1등 공개
- 동점이면 동점 후보와 어필멘트를 먼저 보여준 뒤 1등 공개
- 1등의 어필멘트와 추천인 공개 (추천인은 1등에게만 표시)
- 나머지 후보를 좋아요/싫어요 수, 거부권 여부(🚫)와 함께 순위로 보여줘요.
- 마스코트 아무고릴라(생일 11/14, 말버릇 "고릴래?") 문구 포함

## 📱 사용 시나리오

```
1. 주영이 방을 만들고 방 코드 "A7K2"를 일행에게 공유
2. 혜린·수연이 코드와 닉네임으로 입장 (로그인 없음)
3. 각자 오늘 먹고 싶은 메뉴를 1~3개씩 비공개로 제출
4. 전원 제출 완료 → 주영(방장)이 투표 시작
   → "마라탕 / 마 라 탕" 같은 중복 후보가 자동으로 하나로 합쳐짐
5. 카드를 한 장씩 보며 싫어 / 좋아 버튼으로 선택
   → 카드를 탭하면 어필멘트 확인 가능
6. 싫어하는 후보 중 하나에 거부권 행사 (선택)
7. 전원 투표 완료 → 결과 자동 계산
8. 두구두구 연출 → 👑 오늘의 메뉴: 마라탕 (추천인: 주영, 혜린)
```

## 🎯 기대 효과 및 차별점

### 기대 효과
- 결정 과정의 갈등 없이 모두가 납득할 수 있는 결론을 빠르게 도출해요.
- 거부권 제도로 "정말 싫은 것"은 걸러낼 수 있어요.
- 익명 투표로 눈치 보지 않고 솔직하게 선택할 수 있어요.

### 기존 방식과의 차별점

| | 기존 투표 앱 | 아무거나 말고 |
|---|---|---|
| 후보 수집 | 방장 혼자 입력 | 참여자 전원이 비공개로 제출 |
| 중복 처리 | 수동 | 공백·대소문자 자동 통합 |
| 거부권 | 없음 | 1인 1개 행사 가능 |
| 동점 처리 | 없음 | 어필멘트 공개 후 랜덤 |
| 추천인 익명성 | 없음 | 투표 중 비공개, 1등만 공개 |
| 설치·로그인 | 필요한 경우 多 | 불필요 (방 코드 + 닉네임만) |

## 🛠 기술 스택

| 구분 | 기술 |
|---|---|
| 프론트엔드 | React 19 + TypeScript 5.7 + Vite 6 + Tailwind CSS v4 |
| 폰트 | Pretendard Variable (CDN) |
| 백엔드 | Python 3.11 + FastAPI |
| 데이터 저장 | 백엔드 프로세스 메모리 (DB 없음, 서버 재시작 시 초기화) |
| 인증 | 없음 (방 코드 + 닉네임 + UUID member_id) |
| 세션 저장 | 브라우저 sessionStorage (탭마다 독립) |
| 외부 API / AI | 없음 |
| 화면 갱신 방식 | 프론트엔드 2초 주기 GET 폴링 |

## 🚀 설치 및 실행

### 사전 준비
- Python 3.11 이상
- Node.js 18 이상

---

### 백엔드

**macOS**
```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install fastapi uvicorn
uvicorn main:app --reload --port 8000
```

**Windows (cmd)**
```cmd
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install fastapi uvicorn
uvicorn main:app --reload --port 8000
```

API 문서: `http://localhost:8000/docs`

---

### 프론트엔드

**macOS / Windows 공통**
```bash
cd frontend
npm install
npm run dev
```

앱 주소: `http://localhost:5173`

---

### 환경변수 설정 (선택)

기본값은 `http://localhost:8000`이에요. 백엔드 주소가 다르다면 `.env` 파일을 만들어 설정해요.

```bash
# frontend/.env
VITE_API_URL=http://localhost:8000
```

`.env.example` 파일을 복사해서 사용하세요.

---

### 연동 확인

1. 백엔드 서버를 먼저 실행해요 (`--port 8000`).
2. `frontend/src/api.ts`의 `USE_MOCK`이 `false`인지 확인해요 (현재 기본값: `false`).
3. `npm run dev`로 프론트엔드를 실행하고 `http://localhost:5173`에 접속해요.
4. 두 개의 브라우저 탭으로 방 만들기부터 결과까지 전체 흐름을 확인해요.

> `USE_MOCK = true`로 설정하면 백엔드 없이 목 데이터로 화면을 확인할 수 있어요.
