# UI 가이드 — 아무거나 말고

> 목적: 작은 결정을 즐겁고 깔끔하게. 아무고릴라의 귀여움 + 깔끔한 카드 UI.
> 타깃: 대학생, 20~40대 → 귀엽지만 유치하지 않게, 읽기 편하게.
> 원칙: 밝은 배경 + 핑크 포인트 + 중앙 정렬 카드 + 넉넉한 여백.

## 0. 레퍼런스

| 구분 | 이름 | 링크 | 가져올 것 |
| --- | --- | --- | --- |
| 랜딩 | TAPTAP | https://taptap.inpix.com/ | 큰 굵은 제목, 큰 카드, 깔끔한 흑백 대비 |
| 랜딩 | TAPTAP (GDWEB) | https://www.gdweb.co.kr/sub/view.asp?Txt_fgbn=5&str_no=25881 | 심플한, 깔끔한, 신뢰적인 분위기 |
| 입력 흐름 | Calendly 예약 화면 | https://calendly.com/d/5gw-xzj-33h/dipa-inhouse-meeting-discussion?month=2026-12 | 한 화면에 한 가지씩, 단계별 진행 |

- 레퍼런스의 사진, 로고, 문구는 쓰지 않는다. 배치와 분위기만 참고한다.

## 1. 브랜드

### 서비스와 마스코트

- 서비스 이름: 아무거나 말고
- 마스코트: 아무고릴라 (생일 11/14, 말버릇 "고릴래?")
- 이미지 파일: `frontend/public/`에 넣고 사용한다 (예: `/gorilla.png`). 모든 이미지에 `alt="아무고릴라"`를 쓴다.

### 아무고릴라 사용 위치

| 화면 | 사용 방법 |
| --- | --- |
| 홈·랜딩 | 제목 옆 또는 위에 크게 (120~160px), 말풍선 "고릴래?" |
| 로딩 | 작게 (64~80px) + "고릴래? 잠깐만요…" 문구 |
| 결과 화면 | 1등 카드 옆에 축하하는 모습 (80~120px) |
| 결과 공개 연출 (Should) | 두구두구 동안 가운데 등장 → 1등 공개 |

- 그 외 화면(대기실, 투표, 거부권)에는 넣지 않는다. 화면이 복잡해지지 않게.

## 2. 색상

### 기본 색

| 토큰 이름 | 값 | 용도 |
| --- | --- | --- |
| bg | #FFF8FA | 페이지 배경 (아주 연한 핑크빛 화이트) |
| surface | #FFFFFF | 카드, 입력창 배경 |
| border | #F0E4E8 | 카드 테두리, 구분선 |
| text-primary | #1A1A1A | 제목, 본문 |
| text-secondary | #6B6B6B | 설명, 보조 글자 |
| text-muted | #A3A3A3 | 플레이스홀더, 비활성 |
| danger | #D64545 | 싫어, 거부권, 오류 |
| success | #2F9E6B | 제출 완료 표시 |

### 포인트 색 (아무고릴라 핑크)

| 토큰 이름 | 값 | 용도 |
| --- | --- | --- |
| pink-soft | #FCE4EC | 선택된 항목 배경, 배지 배경, 결과 카드 배경 |
| pink-light | #F6A9BE | 아무고릴라 관련 장식, 진행 바, 스와이프 좋아 효과 |
| accent | #C2456E | Primary 버튼, 강조 글자, 왕관 주변 강조 (흰 글씨 대비 4.5:1 이상) |

- 연핑크(pink-light)에는 흰 글씨를 올리지 않는다. 흰 글씨가 들어가는 버튼은 accent를 쓴다.
- 진한 검정 배경은 쓰지 않는다. 전체적으로 밝게.
- 색만으로 의미를 구분하지 않는다. 좋아/싫어는 항상 아이콘과 글자를 같이 표시한다.

## 3. 글꼴과 글자 크기

- 글꼴: Pretendard 하나만 쓴다.
- 본문 줄간격 1.6, 큰 제목은 `tracking-tight`

| 용도 | 크기 | Tailwind |
| --- | --- | --- |
| 랜딩 대제목 (서비스 이름) | 48~64px, 굵게 | text-5xl ~ text-6xl, font-bold |
| 화면 상단 주제 | 24~28px, 굵게 | text-2xl, font-bold |
| 투표 카드 후보 이름 | 32~40px, 굵게 | text-3xl ~ text-4xl, font-bold |
| 결과 1등 이름 | 40~48px, 굵게 | text-4xl ~ text-5xl, font-bold |
| 본문, 어필멘트 | 16px | text-base |
| 보조 설명, 안내 문구 | 14px | text-sm, text-secondary |
| 라벨, 진행 표시 | 12~14px | text-xs ~ text-sm, text-muted |

## 4. 레이아웃

- 모바일 우선. PC에서는 화면 가운데에 카드형 화면을 띄운다.
- 앱 화면(대기실, 투표, 거부권, 대기, 결과) 최대 폭: 448px (`max-w-md`), 가운데 정렬
- 랜딩(홈)만 조금 넓게: 최대 768px (`max-w-3xl`)
- 좌우 여백 16px (`px-4`), 카드 안쪽 여백 24px (`p-6`), 요소 사이 간격 16px (`gap-4`)
- 모든 화면 상단에 현재 주제를 크게 표시한다 (홈 제외).
- 한 화면에는 한 가지 일만 시킨다 (Calendly처럼).

## 5. 모양

| 요소 | 규칙 | Tailwind |
| --- | --- | --- |
| 카드 | 큰 둥근 모서리, 얇은 테두리, 그림자 거의 없음 | rounded-3xl, border, bg-white, shadow-sm |
| 버튼 | 완전히 둥글게 | rounded-full |
| 입력창 | 둥글게 | rounded-2xl |
| 배지 | 완전히 둥글게, 작게 | rounded-full, px-3, py-1, text-xs |

## 6. 버튼 색상 체계

| 종류 | 모양 | 쓰는 곳 |
| --- | --- | --- |
| Primary | accent 배경 + 흰 글씨 | 방 만들기, 제출, 투표 시작, 좋아, 새로 결정하기 |
| Secondary | 흰 배경 + border + 검정 글씨 | 코드로 참여하기, 거부 안 할래요 |
| Danger | danger 배경 + 흰 글씨 | 싫어, 이걸로 거부 |

- 높이 48px (`h-12`), 작은 버튼 40px (`h-10`), 터치 영역 최소 44px
- 비활성 버튼: 회색 배경 + text-muted, 누를 수 없음 (예: 전원 제출 전 투표 시작)
- 요청 중에는 버튼을 비활성화하고 "잠깐만요…" 표시

## 7. 화면별 UI

### 홈·랜딩 (TAPTAP 스타일)

- 아무고릴라 + 말풍선 "고릴래?"
- 큰 제목: 아무거나 말고
- 한 줄 소개 (택1): "아무거나 말고, 다 같이 정해요" / "고민은 짧게, 결정은 확실하게"
- 큰 카드 2개: "방 만들기" (Primary) / "코드로 참여하기" (Secondary)
- 방 만들기 선택 시: 닉네임 입력 → 주제 버튼 4개 (🍽️ 메뉴 / 🎬 영화 / 📍 장소 / ✏️ 직접 입력) → 주제 입력

### 대기실 + 후보 제출

- 상단: 주제 (크게), 방 코드 배지 (크게, 눌러서 복사)
- 참여자 목록 + "6명 중 4명 제출 완료" 진행 바 (pink-light)
- 안내 문구 (text-sm): 💡 표준 표기법으로 등록해 주세요. 글자가 같으면 같은 후보로 합쳐져요. (예: 떡볶이 ⭕ / 떡복이 ❌)
- 후보 입력 카드 3개: 후보 이름 입력 + 어필멘트 입력 (50자, 글자 수 표시 "12/50")
- 제출 버튼 (Primary) → 제출 후 입력 카드는 회색으로 잠김 + "제출 완료 ✓" 배지
- 방장만: 투표 시작 버튼 (전원 제출 전 비활성)

### 카드 투표 (단어 암기장 스타일)

- 상단: 주제 + 진행 표시 "3 / 7"
- 가운데: 큰 카드 1장 (세로형, 화면 폭에 맞게, 비율 약 3:4)
  - 앞면: 후보 이름 (크게, 가운데)
  - 뒷면: 어필멘트 목록 (말풍선 모양, 익명), 없으면 "어필 없이 등록된 후보예요 🤐"
  - 안내 문구: "카드를 눌러 어필멘트를 확인해 보세요"
- 카드 아래: 👎 싫어 (Danger) / 💗 좋아 (Primary) 버튼 2개, 같은 크기로 나란히

### 스와이프 시각 효과

- 왼쪽으로 끌면: 카드가 왼쪽으로 기울고, 카드 위에 빨간 테두리 + "👎 싫어" 표시
- 오른쪽으로 끌면: 카드가 오른쪽으로 기울고, 카드 위에 핑크 테두리 + "💗 좋아" 표시
- 끌수록 표시가 진해진다. 기준 거리보다 짧으면 제자리로 돌아온다.

### 카드 전환 효과

- 선택하면 카드가 선택한 방향(싫어 왼쪽, 좋아 오른쪽)으로 날아가고, 다음 카드가 뒤에서 살짝 커지며 등장한다.
- 다음 카드는 항상 앞면으로 시작한다.

### 거부권

- 상단: "🚫 거부권은 딱 1장!" + "정말 싫은 후보 하나만 골라 주세요"
- 내가 싫어한 후보 목록 (작은 카드), 하나만 선택 가능 (선택 시 danger 테두리 + 체크)
- 하단: 거부 안 할래요 (Secondary) / 이걸로 거부 (Danger, 선택 전 비활성)

### 대기 화면

- "다른 사람들이 고르는 중이에요"
- "6명 중 3명 완료" 진행 바 + 참여자 목록 (완료한 사람에게 ✓ 배지)

### 동점 후보 공개

- "⚖️ 동점이에요!" 제목
- 동점 후보 카드들을 나란히 (2개면 좌우, 3개 이상이면 세로 목록), 각 카드에 이름 + 어필멘트
- 잠시 후 "고릴래? 🎲" 문구와 함께 랜덤으로 정해진 1등 공개로 넘어간다.

### 결과 화면

- 상단: "'오늘 점심 뭐 먹지?'의 결과는…"
- 1등 카드: pink-soft 배경, 👑 왕관 + 이름 (아주 크게), 어필멘트, 그 아래 "추천인 : 주영, 혜린", 옆에 아무고릴라
- 그 아래 나머지 후보 리스트: 순위, 이름, 💗 좋아요 수, 👎 싫어요 수, 거부된 후보는 🚫 + 흐리게
- 하단: 새로 결정하기 (Primary)

## 8. 상태 표시

- 로딩: 아무고릴라 (작게) + "고릴래? 잠깐만요…"
- 오류: 팝업, 모달, alert 없이 화면 안에 danger 색 문구로 표시 + 필요하면 다시 시도 버튼
- Mock 데이터로 보여줄 때는 화면 구석에 "예시 데이터" 배지

## 9. 움직임

- 라이브러리: motion (`motion/react`)
- 화면 전환: 아래에서 위로 살짝 페이드인 (0.3~0.5초)
- 카드 뒤집기: 세로축 기준 회전 (0.4초)
- 카드 스와이프·전환: 위 7번 규칙
- 버튼 클릭: 살짝 눌림 (scale 0.98)
- 결과 공개 연출 (Should): 두구두구 2초 → 아무고릴라 등장 → 1등 카드가 커지며 등장
- 사용자가 '동작 줄이기' 설정을 켰다면 애니메이션을 끈다.

## 10. 문구 톤

- 친근한 존댓말 "~해요" 체, 문장은 짧게
- 아무고릴라 말버릇 "고릴래?"는 로딩, 결과 공개처럼 기다리는 순간에만 쓴다 (남발하지 않기)
- 버튼은 동작으로: "방 만들기", "제출하기", "투표 시작", "새로 결정하기"

## 11. 반응형과 접근성

- 모바일 우선, PC는 가운데 카드 (`max-w-md`)
- 글자와 배경 명도 대비 4.5:1 이상 (흰 글씨는 accent·danger 위에만)
- 키보드 포커스가 보이게 한다 (`focus-visible` 링)
- 좋아/싫어는 색과 함께 아이콘·글자로 구분

## 12. 개발 규칙 (Kiro용)

- 색은 위 토큰 이름(bg, surface, border, text-primary, text-secondary, text-muted, danger, success, pink-soft, pink-light, accent)으로 Tailwind v4 `@theme`에 등록하고, 코드에 색 코드를 직접 쓰지 않는다.
- 공통 컴포넌트는 `src/components`에 만든다 (Button, Card, Input, Badge, ProgressBar, GorillaMascot, ErrorText, Loading).
- API 응답 필드 이름은 snake_case 그대로 쓴다.
- 동작이 먼저, 꾸미기와 애니메이션은 나중에 한다.
